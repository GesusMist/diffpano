7. TIME TRAVEL: WHAT "ORIGINAL NOISE" MEANS
======================================================================

Original noise is the unscaled local native Gaussian epsilon_init[v]
produced by GWTFlow for camera v.

It is NOT:
    the global ERP parent field
    a newly sampled Gaussian
    the current predicted epsilon
    a current model-implied endpoint
    decoded/encoded noise
    noise warped between cameras

The initializer returns:

    initial_state[v] =
        native_initial_noise_sigma * epsilon_init[v]

Recover epsilon_init using that scale, or expose it through a study-local
wrapper without changing GWTFlow's random draws.

For current unit-scale backends this should be bitwise identical.

For a nonunit-scale test backend, use finite-precision tolerance rather than
requiring division to reverse floating-point multiplication bitwise.

Store one immutable CPU FP32 noise bank.
Do not serialize this large bank to disk.

Do not let it alias evolving states.
Do not modify it in place.

Record its hash before and after generation.

For old89, use the historical canonical camera IDs 0,...,88 so the
GWTFlow states reproduce existing initialization hashes.

The global ERP source and graph buffers are still released after the
one-time initializer.

Only T1 needs to retain the original-noise bank during denoising.

9. TIME TRAVEL: IMPLEMENT THIS EXACT BACKWARD FUNCTION
======================================================================

API:

    backward_original_noise(
        x_low,
        epsilon_init,
        *,
        alpha_low,
        sigma_low,
        alpha_high,
        sigma_high,
    ) -> x_high_revisited

Implement:

    ratio = alpha_high / alpha_low

    x_high_revisited = (
        ratio * x_low
        + (sigma_high - ratio * sigma_low) * epsilon_init
    )

Require:
    identical native tensor shapes
    matching device/dtype after explicit conversion
    finite scalar coefficients
    alpha_low > 0
    finite output
    valid high/low noise ordering for the prepared interval

Do not clamp coefficients.

For straight flow, alpha=1-sigma, so this is equivalent to:

    x_high_revisited = (
        x_low
        + (sigma_high-sigma_low)
          * (epsilon_init-x_low)/(1-sigma_low)
    )

This is the original-noise-directed Euler move in increasing flow sigma.

For SD2, retain the generalized coefficient formula.
Do not call it Euler in the integer DDPM timestep variable.

The equivalent clean anchor:

    c_anchor = (x_low - sigma_low*epsilon_init)/alpha_low

is algebraic only. Never decode it or treat it as a new model clean
prediction.

Do NOT implement:
    x_low + delta_sigma*epsilon_init
    restoring the old cached x_high
    negating a cached model velocity
    using pair.endpoint instead of epsilon_init
    mixing original noise with an unrelated clean estimate
    fresh stochastic forward diffusion

No model call, VAE call, RGB projection, or random draw occurs here.

Tiny required numerical examples:

Flow:
    sigma_low=0.4, sigma_high=0.5
    alpha_low=0.6, alpha_high=0.5
    x_low=0.2, epsilon_init=1.4
    expected x_high_revisited=0.4

DDIM-like coefficients:
    alpha_low=0.8, sigma_low=0.6
    alpha_high=0.6, sigma_high=0.8
    expected:
        x_high_revisited = 0.75*x_low + 0.35*epsilon_init

14. CEA GEOMETRY AND SAMPLING
======================================================================

Normalized mapping:

    u = remainder((longitude + pi)/(2*pi), 1)
    v = (1 - sin(latitude))/2

Inverse:

    longitude = 2*pi*(u - 0.5)
    s = 1 - 2*v
    latitude = asin(s)

Use the existing world convention:
    +Y up
    longitude atan2(world_x, world_z)

CEA pixel-center rays:

    u = (column+0.5)/W
    v = (row+0.5)/H
    s = 1-2*v
    lambda = 2*pi*(u-0.5)

    world = [
        sqrt(max(0,1-s*s))*sin(lambda),
        s,
        sqrt(max(0,1-s*s))*cos(lambda)
    ]

Native CEA raster:
    H=2048, W=4096

This fixed 2:1 storage aspect is deliberate.
Equal-area sampling does not require changing the pixel budget.

Each texel represents:

    area = 4*pi/(H*W)

Do not apply an extra cos(latitude) multiplier to CEA fusion weights.

Perspective -> CEA:

    iterate CEA target rays
    rotate rays into source camera
    compute perspective normalized coordinates
    require positive camera depth and in-FoV coordinates
    bilinearly sample perspective RGB and existing center weights
    accumulate valid weighted RGB and weight sum

CEA -> perspective:

    compute existing perspective pixel-center world rays
    convert them to CEA u,v
    sample the CEA canvas using nearest interpolation in the interior,
    matching the baseline canvas-to-view interpolation choice

Use align_corners=False and explicit pixel-center conventions.

Horizontal interpolation must wrap circularly.

Cache keys must include:
    projection
    height/width
    camera pose/FoV/raster
    interpolation where relevant
    device/dtype

Never share an ERP projection grid with a CEA request.

15. FIXED CEA POLAR-BOUNDARY RECONSTRUCTION
======================================================================

Do not blindly copy ERP vertical-reflection padding into CEA.
Uniform sine-latitude rows are not uniform latitude rows.

Use this explicit study convention:

A. During CEA accumulation, additionally sample the two exact world rays:

       north = (0,+1,0)
       south = (0,-1,0)

   For each source perspective image:
       test visibility
       use the same bilinear source RGB sampling
       use the same source-view center weighting

   Fuse these into two RGB boundary values P_north and P_south.

   These are tiny transient RGB boundary samples, not latent states.
   They add no denoiser or VAE calls.
   Require positive pole weight sums.

B. The first CEA row is at:

       s0 = 1 - 1/H
       theta0 = acos(s0)

   where theta is polar angle from the north pole.

   For a target ray with 0 <= theta < theta0:

       a = theta/theta0

       output =
           (1-a)*P_north
           + a*longitude_sample(first_CEA_row, lambda)

   Use the mirrored construction at the south pole.

C. Outside these unsampled polar caps, use ordinary CEA sampling with the
   configured interpolation.

D. At the exact poles:
       output must equal the fused pole RGB
       and be independent of arbitrary longitude

E. Do not smooth any additional rows.
   Do not use this rule as an appearance-tuning parameter.

Document this as our CEA boundary reconstruction convention, not a theorem
about the projection or an exact author-provided implementation.

Use the same rule during:
    CEA -> perspective synchronization
    CEA -> ERP export
    direct diagnostic view rendering

Record the two terminal RGB pole values in metadata.

The two CEA-specific controls C0 and C1 use the identical rule.
The historical ERP implementation remains unchanged.
