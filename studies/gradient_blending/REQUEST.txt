======================================================================
1. OBJECTIVE AND STRICT SCOPE
======================================================================

We currently fuse inverse-projected predicted-clean RGB views into an ERP
canvas using weighted RGB averaging.

We want to test whether reconstructing the consensus image from a gradient
guidance field can preserve local details better than RGB averaging, without
introducing unacceptable color drift, ghosting, or panorama discontinuities.

Implement three selectable experimental modes:

  rgb
      Exact existing weighted-RGB fusion baseline.

  poisson_mean
      Weighted-average source gradients, followed by a color-anchored
      screened-Poisson reconstruction. This is a CONTROL.

  poisson_select
      Gradients selected from a geometrically reliable source view,
      followed by the same screened-Poisson reconstruction.
      This is the main detail-preservation candidate.

Important:
- Gradient-domain blending here means spatial image derivatives.
- It does NOT mean backpropagating a loss through the diffusion model.
- It does NOT mean modifying model weights, latent guidance, noise warping,
  or the denoiser.
- Do not promise that either variant will improve the results.

Keep blending at EVERY existing denoising interval. Do not implement
intermittent blending, early-only blending, or independent late denoising.
Those belong to a separate future task.

Do not change:
- GWTF/shared-noise initialization;
- native noisy-state semantics;
- current-state interpolation;
- local identity-preserving VAE residual correction;
- model checkpoints, revisions, precision, or conditioning;
- scheduler timesteps, sigma schedule, step count, or guidance;
- camera poses, count, ordering, FOV, or prompt routing;
- ERP/view resolution;
- projection interpolation or spatial confidence weights;
- historical RGB, DPA, LPW, CEA, and SphereDiff experiments;
- existing metric definitions.

Do not introduce a persistent spherical/ERP latent representation.
Do not introduce sharpening filters or call them gradient-domain fusion.

3. IMPLEMENT THE ERP GRADIENT-FUSION OPERATOR
======================================================================

Keep the implementation model-independent.

Prefer:
- one focused reusable implementation module, for example
  diffpano/gradient_fusion.py;
- focused tests;
- a small study-local integration/runner following repository conventions.

Do not duplicate the denoising loop or restructure the repository.

Preserve the original CanvasOperator and its historical B0C0D1 guards.
Use a study-local operator wrapper/subclass or a narrow explicit injection
point whose default delegates to the original implementation unchanged.

In particular:
- do not globally replace RGBFusionAccumulator;
- do not weaken historical validation so arbitrary configurations pass;
- keep the baseline fusion config separate from gradient-study settings;
- unsupported domains/modes must fail explicitly rather than silently
  becoming RGB averaging.

For this task, support ERP. Do not implement CEA gradient blending yet.

3.1 Construct the RGB reference

Let v_i(p) be a view's already inverse-projected RGB value at ERP pixel p,
m_i(p) its validity mask, and a_i(p) its effective baseline fusion weight.

Compute the reference image R with the EXACT existing RGB accumulator.

Do not substitute an unweighted average.
Do not alter the existing handling of positive but very small center weights.
Do not clamp valid weight denominators in a way that darkens the reference.

The rgb experimental mode must directly delegate to the original path,
without extra random draws or changes in floating-point reduction order.

3.2 Define ERP graph edges

Use forward finite differences on the common ERP grid:

  horizontal: p -> pixel immediately to the right, wrapping modulo W;
  vertical:   p -> pixel immediately below, only within the image.

For edge e = (p,q):

  D_e I = I(q) - I(p)

Important boundaries:
- horizontal wrap is a normal adjacent-pixel edge;
- do not force the first and last columns to have identical RGB values;
- do not connect the top row to the bottom row;
- do not zero-pad a derivative stencil across a missing image boundary;
- do not use a 2D periodic FFT that accidentally treats ERP as a torus.

This first implementation is an ERP-grid gradient objective, NOT a
rotation-invariant spherical-gradient objective. Document that limitation.
Do not silently add latitude weighting or a spherical Laplacian.

Use pixel-unit differences consistently and document the convention.

3.3 Compute gradients from individual valid contributions

For each view and edge, compute:

  d_i(e) = v_i(q) - v_i(p)

only when BOTH endpoints are valid in THAT SAME VIEW.

Use an edge-confidence weight such as:

  s_i(e) = min(a_i(p), a_i(q))

with s_i(e) = 0 when either endpoint is invalid.

Never:
- differentiate mask boundaries as though they were image edges;
- subtract values from two different source views to form one source gradient;
- include invalid zero-filled pixels;
- allow NaN values outside valid support to propagate via "0 * NaN".

Validate finite values on valid support and use safe masking.

Compute gradients AFTER inverse projection for this implementation.
Do not warp native perspective gradients without the required coordinate
transformation.

3.4 poisson_mean guidance

For each supported edge:

  g_mean(e) = sum_i s_i(e) d_i(e) / sum_i s_i(e)

Use positive-weight normalization without an arbitrary large denominator
floor. Handle the zero-support case explicitly.

This is a control, not an assumed improvement:
with spatially constant weights, averaging gradients commutes with averaging
images. Do not claim that gradient averaging alone necessarily preserves
more detail.

3.5 poisson_select guidance

For each supported edge, select:

  i*(e) = argmax_i s_i(e)
  g_select(e) = d_i*(e)

Requirements:
- select using existing smooth GEOMETRIC confidence, not raw gradient magnitude;
- use a stable camera ID for deterministic tie-breaking;
- use the SAME source for all RGB channels of an edge;
- derive each selected difference from that source's two endpoint values;
- do not first build a hard RGB mosaic and then differentiate it;
- do not introduce random or camera-iteration-order-dependent ownership.

With fixed cameras and masks, ownership should be geometry-driven and
consistent across denoising steps. Cache geometry-only data where practical.

Save or summarize owner-map boundaries. Source selection may introduce
inconsistent guidance near ownership transitions, so inspect this failure
mode rather than assuming it is solved by Poisson reconstruction.

3.6 Reconstruct the image

Use the same reconstruction objective for both gradient variants:

  E(I) =
      lambda_color * sum_p ||I(p) - R(p)||^2
      + sum_e M(e) ||D_e I - g(e)||^2

where:
- lambda_color > 0;
- M(e) = 1 when at least one valid same-view source gradient exists;
- M(e) = 0 otherwise.

Use binary edge support for the first experiment. Do not use raw summed
center weights in the reconstruction penalty, since that would introduce
another confidence-scale/camera-density effect.

For missing gradient support, omit the edge penalty.
Do not replace missing guidance by a zero-gradient constraint.

Implement the equivalent correction solve, I = R + u:

  A u = b

  A = lambda_color * Identity + D^T M D
  b = D^T M (g - D R)

This makes the RGB reference explicit and gives an exact zero-correction
case when g = D R.

Derive D^T from the implemented discrete edge operator.
Do not guess divergence signs or boundary terms.

Start with:
  lambda_color = 0.1
  solver = matrix-free preconditioned conjugate gradient
  preconditioner = Jacobi
  max_iterations = 200
  relative_tolerance = 1e-5
  absolute_tolerance = 1e-7

These are initial experimental defaults, not established optimal values.

Use FP32 accumulation and production solving, outside mixed-precision
autocast. Use a float64 reference solve for tiny correctness tests.

Do not clamp I during the evolving generation.
Preserve existing preview/final image conversion behavior.

Use a true-residual stopping check:
  ||A u - b|| <= absolute_tolerance + relative_tolerance * ||b||

Handle the zero-right-hand-side case without division by zero.

Record convergence, iterations, initial/final true residual, objective,
correction magnitude, and solve time.

An unconverged or nonfinite solve must fail the experimental run clearly.
Do not silently use RGB fallback and report it as successful gradient fusion.

3.7 Preserve streaming memory behavior

Do not store all 89 full-resolution warped ERP images.

Accumulate only the statistics needed for:
- the exact RGB reference;
- gradient numerator/denominator, or selected gradients and owner IDs;
- edge support;
- solver workspaces and diagnostics.

Keep peak memory O(B*C*H*W) with respect to camera count.

Do not use a dense production matrix or a CPU transfer of full-resolution
arrays on every solver iteration.

======================================================================
5. CORRECTNESS TESTS BEFORE REAL GENERATION
======================================================================

Add automated tests that require no model downloads.

At minimum:

A. Baseline regression
   rgb mode reproduces the unmodified accumulator and pipeline behavior.
   Existing tests continue to pass.

B. Adjoint and system tests
   Numerically verify:
     <D x, y> = <x, D^T y>
   Check symmetry and positive definiteness of A for lambda_color > 0.
   Compare PCG against an explicitly assembled tiny float64 system.

C. Identity
   When g = D R, the correction is zero and output equals R.
   Identical valid source images reconstruct themselves.
   Test a single source and constant images.

D. Mask safety
   Invalid source borders do not create artificial gradients.
   Missing edge support does not impose a zero-gradient constraint.
   Invalid-region NaNs do not leak into valid results.
   Nonfinite valid inputs raise a clear error.

E. ERP boundaries
   Horizontal wrap edges work correctly.
   Top and bottom are never connected.
   A smooth horizontally periodic pattern has no artificial seam introduced.

F. Determinism and invariance
   Reordering cameras changes results by no more than declared numerical
   tolerance, with stable owner tie-breaking.
   Duplicating the complete contribution set preserves the result.
   Uniformly scaling positive confidence weights preserves guidance.
   Test very small positive center weights.

G. Color behavior
   Adding the same RGB offset to all sources shifts the result accordingly.
   Measure mean-color drift and out-of-range values before display conversion.

H. Solver failure handling
   Nonconvergence is recorded as failure, not silently accepted.
   Test zero RHS and a deliberately insufficient iteration budget.

I. Backend-neutral integration
   Use lightweight mock predictions/states to verify that only RGB fusion
   changes, while current-state transitions and bridge hooks remain intact.

Include image-based synthetic tests with known target images:
- thin lines and periodic textures;
- smooth color changes;
- controlled view disagreement or small misalignment;
- complementary sharp/blurred source regions.

For known targets, measure reconstruction and gradient error, not just
gradient magnitude. Document where selection produces duplicated edges,
halos, or other failures.

Do not require the new method to win every synthetic example.
Numerical correctness and empirical superiority are different questions.
